# mantrac_parser — Syntactic Analysis, Grammar Parsing & Hardware Interaction

## 1. Package Overview & Purpose

`mantrac_parser` is the syntactic parsing engine of the Mantra language. It transforms a linear stream of lexical tokens produced by `mantrac_lexer` into a structured, strongly-typed Abstract Syntax Tree (`mantrac_ast::Program`).

### Core Responsibilities:
* **Recursive Descent LL(k) Parsing**: Implements a clean, predictive recursive-descent grammar parser with lookahead capabilities.
* **Mantra Grammar Rules Enforcement**: Parses indentation blocks, decorators (`@test`, `@route`), class declarations, single-inheritance hierarchies, function declarations (sync and async), statements, and expressions.
* **Operator Precedence & Associativity**: Parses arithmetic, comparison, logical, and assignment expressions using Pratt-style precedence climbing.
* **Precise Error Diagnostics**: Reports exact file locations (line, column, byte span) and specific diagnostic codes (e.g., `E0001` unexpected token, `E0002` unclosed delimiter).

## 2. Modules, Data Structures & Functions Used

### Key Modules:
* [`src/lib.rs`](file:///Users/user/Documents/workspace/Mantra-Development/mantra_programming_language/crates/mantrac_parser/src/lib.rs): Contains the `Parser` implementation, recursive parsing methods, and error definitions.

### Data Structures & Enums:
* `Parser`: State machine struct containing:
  * `tokens: Vec<Token>`: Contiguous vector of lexical tokens ingested from the lexer.
  * `cursor: usize`: Current read index within the token stream.
* `ParserError`: Syntactic error descriptor containing `message: String`, declaration `span: Span`, and diagnostic error code `code: &'static str`.

### Functions & Methods:
* `Parser::new(tokens: Vec<Token>) -> Self`: Initializes the parser cursor at token index 0.
* `Parser::parse(&mut self) -> Result<Program, ParserError>`: Top-level entry point that loops until `TokenKind::Eof` is reached, assembling top-level `Declaration` objects into a `Program`.
* `Parser::parse_declaration(&mut self) -> Result<Declaration, ParserError>`: Dispatches class declarations (`class Name:`), function declarations (`def name():`), variable declarations (`let`, `mut`), and decorators.
* `Parser::parse_statement(&mut self) -> Result<Statement, ParserError>`: Parses block statements, `if`/`elif`/`else` trees, `while` loops, `for ... in` iterations, `return`, `break`, `continue`, and expressions.
* `Parser::parse_expression(&mut self, min_precedence: u8) -> Result<Expression, ParserError>`: Implements precedence climbing to resolve binary operator priority (multiplication/division over addition/subtraction, logical AND over OR).
* `Parser::match_token(&mut self, kind: TokenKind) -> bool`: Looks ahead at current token and advances cursor if matching.
* `Parser::expect_token(&mut self, kind: TokenKind, code: &'static str, msg: &str) -> Result<Token, ParserError>`: Asserts expected tokens (e.g., closing parenthesis `)`, colons `:`) and returns actionable diagnostics on failure.

## 3. Communication with Low-Level Language Binaries

`mantrac_parser` constructs the foundational intermediate representation from which low-level binaries are generated:

1. **Deterministic Grammar Structure for Low-Level Code Generation**:
   - The parser constructs unambiguous syntax trees. Every expression node (`BinaryExpr`, `CallExpr`, `BlockStmt`) generated by the parser corresponds to a deterministic sequence of instructions in native assembly or C code.
2. **Span Preservation for Low-Level Debug Symbols (`DWARF` / `CodeView`)**:
   - Each AST node retains its lexical `Span` (file offset, line number, column number).
   - Downstream codegen modules use these spans to emit `.loc` assembly directives, generating standard `DWARF` (Linux/macOS) or `CodeView/PDB` (Windows) debug tables. This allows native debuggers (`lldb`, `gdb`) to step line-by-line through native binaries mapped back to original Mantra source code.

## 4. Hardware Interaction: CPU, ALU, and MU (Memory Unit)

### Central Processing Unit (CPU)
* **Call Stack Navigation via Recursive Descent**:
  - Each grammar rule in the parser is represented by an explicit Rust function (`parse_statement`, `parse_expression`, `parse_primary`).
  - Parsing a deeply nested expression creates a chain of physical CPU stack frames, utilizing hardware call and return instructions (`CALL` and `RET` on x86, `BL` and `RET` on ARM).
* **Branch Prediction & Jump Tables**:
  - `match self.peek().kind` compiles down to CPU jump tables or binary search branch trees. Because keywords like `def`, `let`, `if` occur frequently at statement starts, the CPU branch predictor achieves high accuracy.

### Arithmetic Logic Unit (ALU)
* **Precedence Comparison & Boundary Arithmetic**:
  - In `parse_expression`, the parser constantly queries operator precedence levels (stored as `u8` integers). The ALU executes single-cycle comparison operations:
    ```assembly
    CMP al, [current_precedence]
    JBE exit_climbing
    ```
  - Cursor pointer advances (`self.cursor += 1`) perform 64-bit integer additions (`INC` or `ADD cursor, 1`) inside the ALU.

### Memory Unit (MU) / Memory Management Unit (MMU)
* **Linear Memory Traversal of Token Vector**:
  - The entire token stream is stored contiguously in memory within a `Vec<Token>`.
  - As `cursor` advances monotonically, the hardware memory controller executes sequential streaming reads across 64-byte L1 Data Cache lines. Memory prefetchers detect this linear access pattern and pre-fill cache lines ahead of the CPU execution core.
* **Tree Allocation on the Virtual Memory Heap**:
  - As AST nodes (`Expression`, `Statement`) are created, they are allocated on the heap inside `Box<Expression>` pointers.
  - The system memory allocator (`malloc`/`mmap`) provisions heap pages. Nodes created together share temporal and spatial memory locality, reducing paging overhead in the MMU.
