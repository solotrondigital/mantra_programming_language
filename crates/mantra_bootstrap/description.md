# mantra_bootstrap — Self-Hosting Compiler Pipeline & Hardware Interaction

## 1. Package Overview & Purpose

`mantra_bootstrap` is the self-hosting compiler verification and lifecycle management subsystem for the Mantra programming language. Introduced in Mantra v0.3.0, it guarantees that Mantra can reliably compile its own compiler frontend while maintaining a deterministic, trusted bootstrap path from the initial Rust implementation.

### Core Responsibilities:
* **Three-Stage Bootstrap Lifecycle**: Manages Stage 0 (initial trusted Rust compiler), Stage 1 (Mantra compiler built by Stage 0), and Stage 2 (Mantra compiler built by Stage 1).
* **Binary Reproducibility Verification**: Compares Stage 1 and Stage 2 compilation outputs to guarantee bit-for-bit or AST-equivalent reproducible builds.
* **Stable IR Backend Contract**: Enforces a versioned, immutable schema contract (`IrContract`) for intermediate representation across all backends.
* **Compiler Metadata Embedding**: Injects canonical version, commit hash, build timestamp, and bootstrap stage metadata into compiled binary headers.
* **Sandboxed Plugin Interface**: Provides an extension interface with capability-based security gates.
* **Canonical Language Regression Suite**: Executes automated regression tests covering syntax, inheritance, access control, file I/O, process execution, and async coroutines.

## 3. Communication with Low-Level Language Binaries

1. **Stage Artifact Binary Verification**:
   - Compares the raw machine binary outputs (`ELF`, `Mach-O`, or intermediate C99 files) generated by Stage 1 and Stage 2 to detect non-deterministic compilation bugs (e.g., random hash map iteration order affecting binary layout).
2. **Binary Header Metadata Injection**:
   - Writes structured metadata into `.comment` (ELF) or `__common` (Mach-O) binary sections, encoding toolchain origin, stage number, and build hash into every distributed binary.
3. **Recovery Compiler Fallback**:
   - Preserves the native compiled Rust Stage 0 binary on disk as a permanent recovery compiler if self-hosted compiler builds fail.

## 4. Hardware Interaction: CPU, ALU, and MU (Memory Unit)

### Central Processing Unit (CPU)
* **Bootstrap Stage Execution & Multi-Process Orchestration**:
  - Compiling successive stages spawns compiler processes that saturate multiple CPU execution cores, scheduling parallel compilation tasks.
* **Cache Warming & Determinism**:
  - Clean build environments ensure that CPU cache state and memory page fragmentation do not alter the deterministic execution order of compiler passes.

### Arithmetic Logic Unit (ALU)
* **Cryptographic Hash Digest Computation**:
  - In `ReproducibilityChecker`, the ALU executes SHA-256 transformations to calculate 256-bit hashes of binary outputs.
  - Compares hash digests using 64-bit integer equality instructions (`CMP`, `XOR`).

### Memory Unit (MU) / Memory Management Unit (MMU)
* **Isolated Address Spaces**:
  - Each bootstrap stage runs in a distinct virtual memory address space isolated by the operating system MMU and page tables.
  - Memory leaks or pointer bugs in one stage cannot corrupt the memory space of subsequent stages.
* **Large File I/O Buffering**:
  - Stage binaries and source ASTs are buffered in contiguous virtual memory allocations, maximizing memory bus bandwidth during multi-stage compilations.
